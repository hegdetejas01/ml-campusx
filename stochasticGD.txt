# Problem with Batch GD
    1. Lot of computation required for big data
    2. Computationally slow
    3. if X_train is very huge, ram hardware may not support it

# Stochastic GD
    Here, the update is based on the number of data points
    * In, batch GD, 1 epoch updates the parameter only once
    * Whereas in stochastic GD, if i have n examples, n updates happens to the parameter
    * Therefore, it becomes faster
    * At one time, we use only one example, therefore minimal chance of exceeding ram memory
    * Randomly seleting the rows from n examples

    * But it doesn't give steady output all the time


# Mathematics
    Updating the intercept
        for batch GD: dL/dw0 = (-2/n) sum(i=1 to n) (yi - yihat)

        Since in stochastic GD we are working on a single example, the equation gets modified as:
            dL/dw0 = -2 * (y[id]-yhat[id])

    Updating the co-ef
        for batch GD: dL/dwm = -2/n sum(i=0 to n) [(yi - yihat) * Xim]

        Since in stochastic GD we are working on a single example, the equation gets modified as:
            dL/dwm = -2 * (y[id]-yhat[id]) X[idx](m)


# Time Concept
    * For same number of epochs, batch will take less time compared to stochastic
    * Since, stochastic doesn't need as many as epochs taken by batch GD, it reduces the time

# When to use stochastic GD
    1. When data is big (huge rows and huge columns)
    2. When the function is non-convex

# Problems
    1. Even after moving towards the minima, the stochastic GD still fluctuates instead of becoming steady.
    Make use of Learning Schedule: Reducing the learning rate with epochs
